# Three.js 场景风格模块

## 目标与边界

编辑场景内容配置时，可以为每个仪式独立选择 Three.js 渲染风格。首个接入场景是木鱼；纸鹤目前继续使用现有 2D 交互，未来加入 Three.js 场景时复用同一风格模块。风格作用于场景画布中的整体画面，不改变应用文字、按钮、计步、命中判定或奖励。项目目前没有管理后台页面，因此本期通过内容配置文件选择并使用现有发布流程。

## 选择方案

使用后处理 Shader 将正常渲染的场景转换为卡通画面。可选方案包括逐个模型替换卡通材质，以及为每个场景单独写一套特效；前者需要处理每种模型材质与贴图，后者难以供纸鹤等后续场景复用。后处理模块以 renderer、scene、camera 为输入，场景不持有 Shader 实现细节。

内置预设为 `original`、`toon-ink` 和 `toon-soft`。`original` 保留现有渲染，两个卡通预设共用色阶压缩与屏幕空间轮廓 Shader，但使用不同的色阶、描边强度和色调参数。预设是本地可信代码中的白名单，内容包只能选择 ID，不能下发 Shader 源码。

## 配置与发布

木鱼包在顶层增加可选的 `renderStyle` 字段，校验器只接受上述 ID。缺少字段的旧包解析为 `original`，保持缓存和历史清单兼容。`content/woodfish/pack.json` 是远端选择；`content/woodfish/bundled.json` 是离线内置选择，两者独立。发布工具仍用解析后的内容计算指纹，所以只改风格也会产生新版本；客户端沿用后台准备、下次进入试用、首帧成功确认及失败回退。

风格 ID 由包传给木鱼场景的渲染入口，不进入业务状态或用户存档。未来纸鹤 Three.js 引擎应从自己的内容描述读取同一风格 ID，并调用共享模块；本期不创建虚假的纸鹤 3D 包，也不把纸鹤 2D 页面套上 WebGL 滤镜。

## 渲染与生命周期

共享模块提供创建、绘制、调整尺寸和释放资源的接口。`original` 直接调用原有 renderer；卡通模式先绘制到渲染目标，再运行后处理 Shader，保留画布透明度并按设备像素比更新采样尺寸。色阶压缩作用于整体颜色；基于屏幕颜色差异的轮廓线使木鱼、木槌及其阴影更接近插画。渲染顺序保持与当前场景一致，交互仍使用原相机与网格射线检测。

候选内容的首次真实绘制同时验证所选风格。Shader 编译或绘制失败时，风格模块可降级到 `original`，场景继续可用；模型自身失败仍走现有候选包回退。场景卸载、切换候选或 WebGL 上下文丢失时释放后处理渲染目标和材质。风格只随内容包切换，不在正在进行的敲击动画中途变更。

## 验证

- 内容校验覆盖合法预设、非法 ID、旧包缺省及仅改风格引起的新版本指纹。
- 浏览器检查木鱼三种模式、透明背景、尺寸变化、触控/敲击、加载后回退与离开页面后的资源释放。
- 运行现有单元测试、生产构建和场景内容浏览器测试，确认离线内置包与远端包流程。

## 非目标

本期不搭建可登录的管理页面，不改变纸鹤现有页面，也不允许内容包执行自定义 Shader。若后续要精确描绘几何轮廓或按材质指定色板，可在共享模块中扩展法线/深度输入和新的白名单预设。
